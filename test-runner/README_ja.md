# test-runner — Go テストランナー

Go専用の agy 向けMCPプラグインです。1モジュールずつテストし、テスト失敗・ビルド失敗・再実行引数を整理して返します。呼び出しは完了まで待機します。バックグラウンド実行、履歴保存、自動リトライはありません。

## 前提条件とインストール

- `PATH` 上に Go 1.24 以降。対象モジュールが必要とするツールチェーン・依存関係も必要です。
- 配布物は Linux amd64、macOS arm64、Windows amd64。Windowsのプロセスツリー停止にはOS同梱の `taskkill.exe` を使います。

```sh
agy plugin install https://github.com/kwrkb/agy-plugins/test-runner
```

## ツール: `go_test`

| 引数 | 内容 |
| :-- | :-- |
| `module_path` | 必須。`go.mod` があるディレクトリ。相対パスはMCPサーバーの作業ディレクトリ基準なので、絶対パスを推奨します。 |
| `packages` | 空でない文字列配列。既定 `["./..."]`。ローカルパス・import pathを受け付け、解決した全パッケージが対象モジュールに所属し、そのディレクトリ内にあることを確認します。 |
| `run` | 任意。Goの `-run` 正規表現。`/` 区切りのサブテスト指定にも対応します。 |
| `timeout_seconds` | 1～300の整数。既定60秒。探索・ビルド・テスト全体の制限です。停止処理には追加で数秒かかる場合があります。 |

引数例:

```json
{"module_path":"/code/agy-plugins/test-runner/src","packages":["./..."],"timeout_seconds":60}
```

`go list -e -json` でパッケージを解決し、`go test -json -count=1 -timeout=…` を引数配列で起動します。シェルは経由しません。成功結果のキャッシュ利用を無効にし、毎回実行します。`go.work`、`GOFLAGS`、ビルド設定、ツールチェーン指定などのGo環境は継承します。複数モジュールの自動探索は行わず、対象ディレクトリを指定して個別に呼び出します。

任意コマンド、追加フラグ、`.go` ファイル一覧、race・カバレッジ・継続的fuzzing・ベンチマーク用のオプションは提供しません。Exampleやfuzz seedの実行を含む通常の `go test` の動作は維持します。テストは**プロジェクトのコードをサーバーの権限で実行**するため、ファイル変更や通信を行う場合があります。Goも継承した環境に従ってキャッシュ利用・依存取得・ツールチェーン取得を行う場合があります。このプラグイン自体はサンドボックスではなく、ホスト側の実行権限を利用します。

## 結果と再実行

MCPのテキストとしてJSONオブジェクトを返します。

- `status`: `passed`、`failed`、`no_tests`、`timeout`、`cancelled`、`error`。テスト・ビルド失敗は通常の結果、実行エラー・タイムアウト・キャンセルはMCPの `isError` が真になります。
- `exit_code`: Goプロセスの終了コード。取得できない場合は `null`。探索失敗時には探索プロセスの終了コードを返す場合があります。
- `elapsed_seconds`: 全体の所要時間。`packages[].elapsed_seconds` はGoが報告したパッケージ単位の時間です。
- `tests`: `passed`・`failed`・`skipped` の終了イベント件数。**親テストとサブテストの両方を含み**、パッケージのイベントは含みません。全件skipは件数で判別できます。失敗もテスト終了イベントもない場合が `no_tests` です。
- `packages`: 名前順のパッケージ結果。状態はGoの `pass`・`fail`・`skip`、または `incomplete`。失敗テストには名前・ログ・`rerun` 引数を付けます。panicや `TestMain` の終了など、名前付き失敗がない場合はパッケージログを確認します。
- `build_failures`: テスト失敗件数とは別のビルド診断。パッケージIDにテスト用variantの接尾辞が含まれる場合があります。
- `stderr`・`error`: 診断ログ・実行エラーがある場合に返します。
- `logs_truncated`: ログを省略した場合に真。イベントログとstderrの保持は合計1 MiB、返却ログ本文は合計64 KiBを上限とし、名前付き失敗を優先します。JSONエスケープ後の応答サイズはこれより大きくなる場合があります。
- `incomplete`: 中断・不正出力・終了イベント欠落による部分的な結果です。検証完了とは扱わないでください。

失敗の `rerun` オブジェクトを次の `go_test` の引数として使えます。絶対モジュールパスと制限時間を維持し、パッケージを1つに絞り、サブテスト名の各階層をエスケープして完全一致させます。Goはサブテストの探索に親のセットアップも実行します。親と子の失敗は重複するため、グループを再実行するなら親、対象を絞るなら子を選びます。サーバー内に前回の状態は保存しません。

不正JSON、1 MiBを超えるイベント、100,000件を超える結果レコード、8 MiBを超える探索結果は実行エラーです。解析エラー後も出力を読み捨ててパイプの詰まりを防ぎ、全体タイムアウトを適用します。タイムアウト・キャンセル時はUnixのプロセスグループまたはWindowsのプロセスツリーを停止し、パイプ終了待ちにも上限を設けます。意図的にプロセスツリーから離脱したプログラムはこの停止機構の対象外です。

## 開発と検証

`test-runner/src` で `gofmt`、`go vet ./...`、`go test -count=1 ./...` を実行します。テストは第三者依存のない一時モジュールを作成し、実GoのJSON出力・サブテスト再実行・子プロセス停止・MCP stdioを検証します。

リポジトリルートで `./build.sh test-runner`（Windowsでは `./build.ps1 test-runner`）を実行します。配布物は `.go-version` の固定版でビルドし、素の `go build` の成果物では置き換えません。CIではLinux・macOS・Windowsのテストと、Linuxでの脆弱性ポリシー・決定論ビルドの検査を行います。

利用ガイドは [test-runner-gemini](skills/test-runner-gemini/SKILL.md) を同梱します。
