# go-lsp スキル

このスキルは、`go-lsp` プラグインを使用して、Goコードベースにおける定義元の検索、参照元の検索、およびホバー情報の取得を安全かつ効果的に行うための知識を提供します。

## ワークフローの鉄則

1. **インデックス（1-indexed）の指定**:
   `go_definition`、`go_references`、`go_hover` のすべてのツールは、**`line`（行番号）および `character`（文字位置）として 1-indexed（1から始まる数値）** を受け取ります。0-indexed に間違えないよう注意してください。
2. **ワークスペースルートの解決**:
   `dir` 引数は、基本的には自動解決されるため省略可能です（カレントワーキングディレクトリが使用されます）。特定の別プロジェクトやサブモジュールを対象にする場合のみ、絶対パスで明示的に指定してください。

## ツールと使用場面

### 1. `go_definition`（定義元の検索）
関数の実装箇所、構造体の定義箇所、インターフェースの定義箇所を特定する際に使用します。

* **使用タイミング**:
  * 呼び出している関数の具体的なロジックを知りたいとき。
  * 構造体や変数の型定義を確認したいとき。

### 2. `go_references`（参照元の検索）
ある関数や構造体がコードベースのどこで使用されているかを一覧表示します。

* **使用タイミング**:
  * 関数や構造体のシグネチャを変更する際、影響範囲を特定するとき。
  * デッドコード（どこからも参照されていないコード）がないか確認するとき。

### 3. `go_hover`（ホバー情報の取得）
関数のドキュメンテーション（Go Doc）や、変数の型情報を素早く確認します。

* **使用タイミング**:
  * 関数の引数の意味や戻り値の仕様を、実装コード全体を読まずに簡潔に把握したいとき。
  * 複雑なジェネリクスや型推論の結果、最終的にどんな型になっているかを知りたいとき。

## トラブルシューティング

* **`gopls not found in PATH` エラー**:
  実行環境に `gopls` バイナリがインストールされていないか、PATHが通っていません。ユーザーに `go install golang.org/x/tools/gopls@latest` の実行を促してください。
* **検索結果が返ってこない、またはエラーになる場合**:
  指定したファイルパスが存在するか、`line` や `character` の値がファイルサイズを超えていないか確認してください。また、コードがコンパイルできないほど壊れている場合、`gopls` からの部分的な解決が失敗することがあります。
